# Asynchronous FIFO Design using Verilog

## Overview

This project implements a parameterizable **Asynchronous FIFO (First-In First-Out)** using Verilog HDL.

The FIFO transfers data between two independent clock domains using:

* Separate write and read clocks
* Binary read/write pointers
* Gray-code pointer conversion
* 2-flip-flop synchronizers for clock-domain crossing
* Full and empty flag generation
* Registered read data
* Randomized functional verification with a reference queue

The FIFO depth and data width are configurable through Verilog parameters.

---

## Architecture

The asynchronous FIFO consists of two independent clock domains:

### Write Clock Domain

The write side contains:

* Write binary pointer
* Write Gray-code pointer
* Write-side memory operation
* Read-pointer synchronizer
* FIFO full detection

### Read Clock Domain

The read side contains:

* Read binary pointer
* Read Gray-code pointer
* Read-side memory operation
* Write-pointer synchronizer
* FIFO empty detection

Conceptually:

```text
                  ASYNCHRONOUS FIFO
        ┌───────────────────────────────────┐
        │                                   │
wr_clk ─► Write Logic ─► FIFO Memory ─► Read Logic ◄─ rd_clk
        │       │                         │
        │       │                         │
        │ Write Gray                  Read Gray
        │ Pointer                    Pointer
        │       │                         │
        │       ▼                         ▼
        │  2-FF Synchronizer       2-FF Synchronizer
        │       │                         │
        │       ▼                         ▼
        │ Read Pointer              Write Pointer
        │   in wr_clk                 in rd_clk
        │                                   │
        └───────────────────────────────────┘
```

## Why Asynchronous FIFO?

An asynchronous FIFO is useful when data needs to be transferred between two clock domains operating at different frequencies or phases.

For example:

```text
Write Clock = 100 MHz
Read Clock  = ~58.8 MHz
```

The two clocks in the testbench are intentionally different and unrelated.

---

## Gray-Code Pointers

Binary counters can have multiple bits changing during a single increment.

For example:

```text
Binary:

0111 → 1000
```

Four bits change simultaneously.

If such a binary pointer crosses into another clock domain, the receiving domain could temporarily observe an incorrect value.

Therefore, the FIFO converts the binary pointer to Gray code:

```verilog
assign wr_ptr_gray_next =
                (wr_ptr_bin_next >> 1) ^ wr_ptr_bin_next;
```

In Gray code, only one bit changes between consecutive values.

This makes Gray-coded pointers suitable for clock-domain crossing.

---

## Clock-Domain Crossing

The Gray-coded write pointer is synchronized into the read clock domain:

```text
Write Clock Domain
       │
       ▼
Write Gray Pointer
       │
       ▼
     FF1
       │
       ▼
     FF2
       │
       ▼
Read Clock Domain
```

Similarly, the Gray-coded read pointer is synchronized into the write clock domain.

Two flip-flops are used to reduce the probability of metastability propagating into the receiving clock domain.

---

## FIFO Empty Detection

The FIFO is considered empty when the current read pointer is equal to the synchronized write pointer.

```verilog
assign empty = (rd_ptr_gray == wr_ptr_gray_sync2);
```

This means there are no unread entries in the FIFO.

---

## FIFO Full Detection

The FIFO full condition is generated by comparing the next write Gray pointer with the synchronized read pointer, with the appropriate upper Gray-code bits inverted.

```verilog
full <= (wr_ptr_gray_next ==
         {~rd_ptr_gray_sync2[ADDR_WIDTH:ADDR_WIDTH-1],
          rd_ptr_gray_sync2[ADDR_WIDTH-2:0]});
```

The extra pointer bit is used to distinguish between the full and empty conditions when the read and write addresses are equal.

---

## Parameterization

The design uses two parameters:

```verilog
parameter DATA_WIDTH = 8
parameter ADDR_WIDTH = 4
```

FIFO depth is calculated as:

```verilog
DEPTH = 2^ADDR_WIDTH
```

For the default configuration:

```text
DATA_WIDTH = 8 bits
ADDR_WIDTH = 4 bits
FIFO Depth = 16 entries
```

Therefore, the FIFO can store:

```text
16 × 8-bit words
```

## Verification

A dedicated testbench is provided to verify the FIFO.

The testbench includes:

* Independent write and read clocks
* Different clock frequencies
* Randomized write operations
* Randomized read operations
* Reference queue for data comparison
* Full/empty checks
* Data integrity checking
* Simulation timeout protection
* VCD waveform generation

### Clock Configuration

```text
Write clock period = 10 ns
Read clock period  = 17 ns
```

The clocks are intentionally asynchronous to exercise clock-domain crossing behavior.

---

## Reference Queue

A software reference queue is used to verify FIFO data integrity.

```text
Write Data
    │
    ▼
FIFO ───────────────► Read Data
    │                    │
    │                    │
    ▼                    ▼
Reference Queue ───► Compare
```

Every successfully written word is stored in the reference queue.

When data is read from the FIFO, the output is compared against the expected value in the queue.

## How to Run

### Using Vivado

1. Create a new RTL project.
2. Add:

```text
rtl/async_fifo.v
tb/async_fifo_tb.v
```

3. Set `async_fifo_tb` as the simulation top module.
4. Run behavioral simulation.
5. Open the waveform viewer.

### Using Icarus Verilog

Compile:

```bash
iverilog -o async_fifo_sim rtl/async_fifo.v tb/async_fifo_tb.v
```

Run:

```bash
vvp async_fifo_sim
```

The testbench generates:

```text
async_fifo_tb.vcd
```

which can be viewed using GTKWave.
